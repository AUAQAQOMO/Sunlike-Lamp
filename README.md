# Sunlike 双色温台灯固件（ESP32-C3 + 2×LGS63042EP）

驱动板：CH224K 诱骗 20V → LGS5145 降压 3V3 → ESP32-C3-MINI-1U-H4；
两片 LGS63042EP 升压恒流分别驱动 3000K / 5700K 灯组（9V×4 串×7 并）。
旋钮 EC11 直接挂在主控上，单板架构。

## 目录结构

```
platformio.ini          PlatformIO 工程配置
src/config.h            所有可调参数（引脚、PWM、交互、云端 Key）
src/pwm_hal.*           LEDC 双通道封装（XTAL 40MHz / 20kHz / 10bit）
src/light_engine.*      混光引擎（gamma2.2、总电流守恒、自适应步进、渐变插值）
src/rotary.*            EC11 正交解码 + 按键状态机
src/state_store.*       NVS 掉电记忆
src/app_link.*          点灯科技米家灯组件 + ArduinoOTA
src/main.cpp            主流程
```

## 一、关键设计

| 项目 | 取值 | 说明 |
|---|---|---|
| LEDC 时钟源 | XTAL 40MHz | 模组内置晶振直连，最稳定 |
| 调光频率 | 20kHz | 分频系数 1.953125 可被 8 位小数分频器精确表示，无频率误差 |
| 分辨率 | 10bit（1024 级） | 40MHz 下 20kHz 的物理上限 |
| 单路满电流 | 666.7mA | `I = 0.2V / 300mΩ`（手册 0.195~0.205V） |
| 亮度曲线 | gamma 2.2 | 感知线性；占空比区间整体抬到 `DUTY_MIN_USABLE` 之上 |
| 总电流约束 | 恒等于单路满电流 | `duty_warm + duty_cool ≤ 1023`，调色温不改变总功率与视觉亮度 |
| 渐变 | 主循环插值（60Hz） | 开灯 1500ms / 关灯 2000ms 柔和过渡；调节按占空比距离自适应 25~400ms |
| PWM 输出 | 全程由 LEDC 硬件产生 | 插值只负责每 16ms 更新一次占空比，波形不受 CPU 影响 |

混光公式（`B` 为亮度 0~1，`T` 为色温 0=3000K、1=5700K）：

```
total = DUTY_MIN_USABLE + (1023 - DUTY_MIN_USABLE) * B^2.2
cool  = round(total * T)          // 5700K 路
warm  = total - cool              // 3000K 路
```

## 二、交互

| 操作 | 行为 |
|---|---|
| 旋转 | 调亮度（1% 步进，暗端自动放大到占空比至少变 1 级） |
| 按住旋钮 + 旋转 | 调色温（2% 步进，共 50 档） |
| 单击（<600ms） | 开灯 / 关灯 |
| 长按 5s | 灯闪 3 下 → 清除配网信息并重启，等待重新配网 |

掉电记忆亮度、色温、开关状态；上电后直接淡入到上次状态。

## 三、构建与烧写

1. 安装 [PlatformIO](https://platformio.org/)（VSCode 插件或 CLI）；
2. 打开 `src/config.h`，把 `BLINKER_AUTH_KEY` 填成点灯 App 里的设备 Key
   （**留空 = 纯本地模式**，不启动 WiFi，旋钮照常工作，可先这样验证硬件）；
3. 编译并烧写：

```bash
pio run -t upload
pio device monitor
```

首次编译需要联网下载 `espressif32@6.9.0`（arduino-esp32 2.0.17）与 `blinker-library`。

## 四、配网与米家

1. 首次上电（或长按 5s 后）设备进入配网模式；
2. 打开**点灯科技 App** → 添加设备 → 按提示给设备配网；
3. 设备在线后，在点灯 App 中开启该设备的米家/小爱支持（菜单名称随 App 版本可能不同），
   之后设备会出现在米家 App 里，小爱可控制开关、亮度、色温。

固件侧做了三件事：米家指令直接驱动本地引擎、本地操作后主动回传状态、
查询指令统一回传完整状态，避免米家 App 显示不同步。

**要注意的限制**（详见对话记录）：米家/小爱必须联网、依赖点灯云服务、
免费额度可能受限、延迟 0.3~2s、米家侧控件只有开关/亮度/色温。
本地旋钮与掉电记忆完全不依赖网络。

## 五、编译状态与上机验证清单

已在本机用 PlatformIO 6.2.0 + `espressif32@6.9.0`（arduino-esp32 2.0.17）编译通过：

```
RAM:   14.8% (48,348 / 327,680 bytes)
Flash: 57.9% (1,139,220 / 1,966,080 bytes)   <- OTA 双分区各 1.875MB
```

仍需上机确认的 3 件事：

1. **最低可用占空比**：把亮度调到最暗，若出现不亮、闪烁或跳变，
   把 `config.h` 里的 `DUTY_MIN_USABLE` 从 8 调大（10~20）；若响应很好可试 5。
2. **输出电容啸叫**：20kHz 正好在人耳上限。若听到细响，把 `PWM_FREQ_HZ` 改为
   22000 或 25000（芯片支持到 100kHz，改后频率误差仍可忽略）。
3. **暗端台阶**：10bit + gamma2.2 在 10% 亮度以下档位较粗（约 6 档）。
   如果觉得不能接受，只能换方案：`APB 80MHz + 19.53kHz + 12bit`（暗端 4 倍精度），
   改动仅限 `pwm_hal.cpp` 的时钟源与 `config.h` 的分辨率。

## 六、硬件侧的两个提醒

- 满功率时输入电流约 1.4A@20V，电感峰值接近芯片 SW 限流下限 1.7A。
  你已确认电感饱和电流 4.5A，但**仍建议先用功率计确认 20V 适配器能稳定给到 30W 以上**，
  否则会在满亮度时周期性限流。
- CH224K 的 PG 引脚没有接到 MCU，固件无法得知适配器实际协商到了几伏。
  如果插入非 PD 的 5V 电源，升压比过大，灯会变暗甚至无法点亮，这是硬件限制。

## 七、为什么渐变不用 LEDC 的硬件 fade

`ledc_set_fade_with_time()`（arduino-esp32 3.x 的 `ledcFade()` 也一样）内部用
**整数 `scale`** 表示“每个 PWM 周期把占空比改变几级”，最小只能取 1。

20kHz / 10bit 下，1 级占空比 = 50µs，满量程 1023 级最快也要 **≈51ms**。
也就是说硬件 fade 能表达的最长满量程渐变只有 51ms，请求 2000ms 只会被压缩成 51ms
（甚至连 `scale` 都算成 0 而直接失败）。**秒级的柔和过渡在硬件 fade 上物理上做不到。**

所以渐变改由 `src/light_engine.cpp` 在主循环里按时间插值：

- 每 `TWEEN_TICK_MS`（16ms，约 60Hz）计算一次当前应达到的占空比并写入 LEDC；
- 时长完全可控：开灯 1500ms、关灯 2000ms、调节按距离 25~400ms；
- 目标中途变化时，从**当前实际输出**重新开始插值，不会跳变；
- PWM 波形本身仍由 LEDC 硬件产生，插值只是周期性改占空比，不影响 20kHz 精度。

这样也顺带解决了 IDF 4.4 的另一个限制——
它**没有 `ledc_fade_stop()`，且渐变进行中 `ledc_set_duty` 会返回
`ESP_ERR_INVALID_STATE`**，导致“必须等上一段渐变走完才能响应新目标”。
现在不存在这个等待，旋钮始终跟手。
